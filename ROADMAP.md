## Product direction

re;Flux is a reactive TypeScript animation library. The core remains headless; rendering adapters are optional. The capabilities below distinguish implemented APIs from remaining hardening and integration work.

## Product principles

- **Observable-first:** Motion, time, and velocity are values in streams—not hidden mutable globals.
- **Headless by default:** Rendering is an adapter concern. Core logic produces values and timestamps.
- **Deterministic tests:** Clock-dependent behavior must be testable with an injected or virtual clock.
- **Honest performance:** Frame alignment reduces redundant work, but cannot guarantee 60 or 120 FPS under browser throttling.

## Capability status

### 01. First-class gesture physics

**Status:** Implemented · hardening ongoing

Turn pointer input into typed motion streams, with drag inertia and following motion as composable RxJS operators.

**Problem:** Drag implementations often mix event listeners, velocity calculations, mutable state, and cleanup in one component.

**Direction:** Keep DOM event normalization optional and put the physics in pure operators that emit position, velocity, and timestamps.

**API example**

```ts
import { map, share } from 'rxjs';
import { pointerGestures$, dragInertia, slideFollow } from '@re-code/flux';

const drag$ = pointerGestures$(element).pipe(
  dragInertia({ friction: 5.5, minVelocity: 8 }),
  share(),
);

const follower$ = drag$.pipe(
  map(({ x, y }) => ({ x, y })),
  slideFollow({ stiffness: 220, damping: 28 }),
);
```

**Acceptance criteria**

- Time-based physics behaves consistently across frame rates.
- Pointer cancellation and unsubscription clean up all listeners.
- Core operators emit data and never write to the DOM.

### 02. Real-time stream smoothing

**Status:** smoothStream and adaptiveTween implemented

Smooth irregular WebSocket, SSE, telemetry, and GPS samples with fixed-latency buffering or cadence-adaptive transition duration.

**Problem:** Rendering each arriving network sample immediately makes motion jump when packet timing varies.

**Direction:** Sample timestamped values against the shared frame clock. smoothStream uses fixed display latency; adaptiveTween estimates input cadence and adjusts the duration between successive targets. Neither operator predicts future data.

**API example**

```ts
import { adaptiveTween, smoothStream } from '@re-code/flux';

const fixed$ = serverSamples$.pipe(
  smoothStream({ targetLatency: 100, interpolate: lerp }),
);
const adaptive$ = serverSamples$.pipe(
  adaptiveTween({ minDuration: 20, maxDuration: 220, durationFactor: 1.5, interpolate: lerp }),
);
```

**Acceptance criteria**

- Frame-aligned interpolation and bounded memory are implemented.
- Duplicate/out-of-order, stale, invalid and finite-source behavior have unit tests.
- adaptiveTween adapts transition duration to cadence; prediction remains intentionally separate.

### 03. Seamless interruption and retargeting

**Status:** Implemented · test hardening ongoing

Switch animation targets without snapping back to the original start value or discarding momentum.

**Problem:** Interrupting a tween can cause visual jumps or force applications to implement cancellation and continuity manually.

**Direction:** Carry the current value, velocity, and timestamp into the next target transition. The operator owns one motion per subscription and waits for the last target to settle after source completion.

**API example**

```ts
import { retargetMotion } from '@re-code/flux';

const motion$ = targets$.pipe(
  retargetMotion({ initialValue: 0, stiffness: 260, damping: 30 }),
);
```

**Acceptance criteria**

- Retargeting starts from the latest sampled value and velocity.
- Source completion waits for the final target to settle; unsubscribe cancels work.
- Rapid target changes and stream errors remain leak-free.

### 04. Frame coordinator

**Status:** Implemented · integration tests ongoing

Coalesce library work into one frame-aligned coordinator with explicit read and write phases.

**Problem:** Independent updates can repeat work or interleave layout reads and DOM writes, causing avoidable layout thrashing.

**Direction:** Reuse RxJS animationFrameScheduler where suitable and add only the library-specific batching coordinator we need.

**API example**

```ts
frameCoordinator.scheduleRead(measureLayout);
frameCoordinator.scheduleWrite(applyStyles);
```

**Acceptance criteria**

- One pending coordinator RAF while work is queued.
- A shared timestamp is passed to every task in a frame.
- Read/write ordering and cancellation semantics are deterministic.

### 05. Headless rendering adapters

**Status:** DOM / SVG / Canvas / Three.js adapters implemented

Connect the same motion streams to DOM, SVG, Canvas, Three.js, or framework state without coupling the core to them.

**Problem:** DOM-first engines make it harder to reuse the same motion logic in Canvas, WebGL, or server-side contexts.

**Direction:** Keep the core headless and publish thin opt-in adapters that own their subscriptions and restore original target state on teardown.

**API example**

```ts
import { bindStyle } from '@re-code/flux/dom';
import { bindSvgAttributes } from '@re-code/flux/svg';
import { bindCanvas } from '@re-code/flux/canvas';
import { bindThreeObject } from '@re-code/flux/three';
```

**Acceptance criteria**

- DOM/SVG adapters restore original styles or attributes on unsubscribe.
- Canvas drawing is coalesced through the shared frame write phase.
- The Three.js adapter uses structural types and adds no Three.js dependency to the core.

### 06. Typed keyframes and DOM targeting

**Status:** Implemented · API integration hardening ongoing

Define explicit start/end values, keyframes, per-property timing, and per-target frames while keeping the DOM adapter optional.

**Problem:** Low-level progress controls are flexible but verbose for common UI tasks, while selector helpers should not force DOM dependencies into the core.

**Direction:** Use one property configuration that accepts from/to, values, keyframes, or a target-aware factory. The factory receives the resolved element, index, and total once at animation creation.

**API example**

```ts
import { animate } from '@re-code/flux/dom';

animate('.card', {
  duration: 400,
  properties: {
    opacity: { from: 0, to: 1 },
    transform: {
      from: 'translateY(16px)',
      to: 'translateY(0px)',
      easing: 'easeOutCubic',
    },
    zIndex: (target, index, total) => [index, total - index],
  },
  stagger: (index) => index * 50,
}).play();
```

**Acceptance criteria**

- Supports selector strings, individual elements, and iterable targets.
- Supports shorthand frames, explicit from/to, normalized keyframes, and target-aware value factories.
- Global and property timing settings have documented precedence and validation.
- Target factories run once per target at creation, not on animation frames.
- DOM adapter remains optional and existing public imports remain stable.

## Implementation order

### Stabilize timeline contracts, benchmark hot paths, then expand the API.

Timeline duration lookup and pre-start resets are now optimized, nested timelines have explicit single-parent ownership, and frame-work timing is collected only while metrics are observed. Remaining work focuses on browser integration, stress coverage, and consumer package smoke tests.

1. **Browser integration coverage:** Test pointer capture and cancellation, style restoration, layout effects, and adapter cleanup in a real browser.
2. **Performance baselines and regression checks:** Track duration lookup, timeline seeking and frame-coordinator overhead with and without metrics observers; compare results across changes.
3. **Stress and property tests:** Exercise irregular streams, rapid retargeting, re-entrant frame scheduling, and subscription cleanup.
4. **Consumer package smoke tests:** Install the produced tarball in a clean fixture and import every documented public entry point.
5. **Complete adapter examples:** Add realistic examples for SVG path morphing, Canvas lifecycle, and structural Three.js integration.

# Publishing and maintenance

This package is ESM-first and publishes only the compiled `dist/` output, its public type declarations, the README, publishing checklist and license. The docs app, demos, tests and benchmarks are not part of the runtime package.

## Before merging changes

Run the same checks locally and in CI:

```bash
npm run typecheck
npm run typecheck:tests
npm test -- --runInBand
npm run check:tree-shaking
npm run check:package
npm run build
```

`check:tree-shaking` bundles representative consumers of the root, core, DOM, SVG, Canvas and Three.js entry points and checks that unrelated adapters are absent. `check:package` audits the file list generated by `npm pack --dry-run`.

## Lockfile and clean installs

Keep the workspace `package-lock.json` committed at the repository root. Generate or update it intentionally when dependency manifests change, inspect the diff, and run `npm ci` from a clean checkout. The current source bundle does not contain a lockfile because the registry could not be reached in the authoring environment; consequently, the docs workflow still has a temporary step that resolves a lockfile on the runner. That step should be removed after the generated lockfile is committed so CI consumes the same dependency graph on every run.

```bash
npm install --package-lock-only --ignore-scripts --no-audit --no-fund
npm ci
```

Do not manufacture or hand-edit integrity hashes in the lockfile. If the registry is unavailable, wait until registry access is restored before updating it.

## Release checklist

1. Ensure the working tree is clean and all validation commands pass.
2. Update the package version with the appropriate semantic-version increment. Before `1.0.0`, document breaking public API changes clearly.
3. Review `package.json` `exports`, `files`, `sideEffects` and peer dependencies. Add a public subpath only when its API is intended to be supported.
4. Confirm the package contents using `npm pack --dry-run` and test the generated tarball in a small consumer project.
5. Authenticate to npm and publish the scoped package publicly:

   ```bash
   npm publish --access public
   ```

6. Verify the published version and metadata, then create a matching Git tag/release.

`prepack` runs the library type checks, tests, tree-shaking checks and package-content audit before a package archive is created. The root `exports` map is the public API contract; internal source paths are not public imports.

## Tree-shaking contract

- Keep `sideEffects: false` only while library modules have no import-time effects. Register listeners, instantiate observers and start clocks only when an API is explicitly called or an object is constructed.
- Keep core modules renderer-independent. DOM, SVG, Canvas and Three.js code must not be imported by the root/core entry points.
- Keep rendering-specific runtime dependencies optional. Prefer structural interfaces for adapters when a third-party runtime dependency is not required.
- Keep decorative scenes inside `apps/docs/src/demos/`. Reusable generic rendering adapters belong in `src/adapters/`; a scene becomes a public extension only after its API and maintenance scope are justified.
